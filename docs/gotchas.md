# Behavior and troubleshooting

- **The wide dictation bar uses one switch.** Its second switch is disabled. The profile sends explicit 40 ms press/release events and no paste step. Preserve those settings to avoid duplicate dictation. If insertion repeats, compare a physical tap with the keyboard shortcut and check that only one helper is running.
- **Layer order is not app identity.** Layers 1/2 are Codex/Chat in ChatGPT; 3/4 are Code/Chat in Claude. All layers send identical action shortcuts. Helper actions use the foreground app, by design.
- **Tab selection and app activation are separate.** Bringing ChatGPT forward is insufficient. Its view switches use Control+1/3, posted once after focus is established. ChatGPT view detection is not inferred from conversation titles.
- **Claude workspace selection requires its sidebar Mode group.** The helper uses the Chat and Cowork / Code pair there, not similarly named controls in the composer. If that group is unavailable or ambiguous, it does not guess a workspace.
- **Shortcut overrides can block actions.** ChatGPT model selection uses Control+Shift+M; this kit sends Control+Shift+D for your configured dictation tool. Check both shortcuts for conflicts with other applications. Restore the required shortcut only after checking what the conflicting binding does.
- **Dictation tools need compatible behavior.** Control+Shift+D must be a global start/stop toggle, with transcription inserted into the focused app. Hold-to-talk-only behavior or insertion into a separate editor does not match this profile. Superwhisper is the maintainer's choice; alternatives require their own four-workspace checks.
- **A Copy tooltip is not an accessibility label.** The visible tooltip can say Copy response while the actual button label is Copy. The helper scopes it to the latest assistant response. Claude may hide the message toolbar until its reveal control is pressed.
- **A Copy button can have a wrapper.** OpenAI response Copy supports a direct button or a one-child group whose only DOM class is `contents`. The helper presses the child button. It does not search arbitrary response-body groups, where code-block Copy buttons can appear.
- **Claude Code can omit message numbers and assistant headings.** The helper follows the final branch inside Chat messages. An unnumbered response must end with its message actions or reveal control, and its toolbar must contain one Copy and one Read aloud or Stop reading control. A user toolbar, ambiguous toolbar or unsupported final branch does nothing. Numbered messages retain the assistant-heading check.
- **An older Copy button is not a fallback.** An OpenAI assistant heading in an unsupported response group blocks selection of an older recognized response. Unknown layouts still require inspection; fixture coverage does not establish compatibility with every app update.
- **Claude permission buttons change names.** Allow once can have suffix 2 or 3, depending on whether Always allow is present. Approval requires one recognized permission group with a unique Allow once/Deny pair. Ambiguity produces a beep, not a blind Return.
- **ChatGPT approval buttons must belong to a permission card.** The helper requires a Permissions application alert beside the marked approval form in the same card. It searches only that form's buttons, never same-named controls elsewhere in the conversation. Missing or multiple permission alerts produce no approval.
- **Y/X are not text editing keys.** With no permission prompt they should not submit, erase or type into a draft. The hand key is ordinary Escape, which has broader app-defined behavior.
- **An approval belongs to the window where the key was released.** If the focused window or matching permission control changes during the modifier-release delay, the helper cancels the action. Press again only after reviewing the current request.
- **Eight joystick directions use screen coordinates.** Down is the sector at quarter-turn; Up is three-quarter-turn. Diagonals are Select all, Tab, Copy and Paste. Copy selection and Copy response are intentionally different controls.
- **Input can cache old radial labels.** Restart Input after a verified device write before assuming the firmware mapping is wrong. Native key labels come from Input and may use lowercase words or glyphs.
- **The dial is arrow navigation, not native scrolling.** Rotating sends the saved Up/Down mapping. Natural-scrolling preferences do not invert key events. Test physical rotation before changing it.
- **Accessibility and Input Monitoring are separate.** Accessibility permits app control; the tested Input-based USB bridge also needs Input Monitoring for Creator Micro AI. If device colors change but no app or view switches, check both permissions. Working Accessibility does not prove that the bridge can read the device.
- **Permission trust follows the installed build.** Ad-hoc rebuilding can leave stale Accessibility and Input Monitoring entries, even when their switches appear enabled. After replacing the build, remove and re-add the installed app in both lists, enable both, then quit and reopen the helper. Verify both permission states in its menu. Changing permissions is a user step, not something the installer bypasses.
- **Apps update underneath us.** Missing or changed selectors should fail closed. English labels, app paths, model shortcuts and internal Input APIs are compatibility constraints, not permanent guarantees.
- **A bridge crash can appear under Input's name.** The helper runs its device bridge using Input's installed runtime. A native HID failure can terminate that child without terminating the helper. The helper reports a signal termination separately from a connection or launch failure, then retries after 3 seconds. Repeated failures increase that delay to at most 30 seconds; a connection lasting 30 seconds resets it. A failed native connection is never reopened in the same child. Status is in memory only. These safeguards do not establish the cause of every vendor-runtime crash.
- **Do not click Reopen during a recovery test.** Wait up to 40 seconds, check Setup & Status, and try the layer cycle. If switching does not recover, record that failure before restarting anything. Normal recovery should not require rewriting the device profile or resetting permissions.
